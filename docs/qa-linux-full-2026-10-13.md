# Linux 功能回归与 Bug 排查（2026-10-13）

本次在 Linux x86_64 云环境测试现有功能，使用自行生成的图形、文字和图片。
没有使用第三方商业绘图应用、用户作品或私有数据。安装集成的独立检查见
[Linux 预览版验收](qa-linux-2026-10-13.md)。

## 发现并修复

1. **CMYK 渐进式 JPEG 重新打开后为空白。** 质量低于 90 时，JPEG 编码器会对 K
   通道采用较高的采样率；主解码器拒绝这种有效文件。外部 Pillow 能正常读取，
   项目此前只读取文件头，因而成功打开却没有显示像素。
   CMYK 像素统一使用 `jpeg-decoder`，限制解码像素数和缓冲区大小，保留原始
   墨量及工作色彩配置的显示方式；吸管、重新着色和图像描摹也能读取这些像素。
   新增 3–5 次扫描、质量 40/80/100 的生成、打开、渲染、采样、重新着色和描摹回归。
2. **损坏 JPEG 被当成正常图片打开或置入。** 合法文件头之后没有压缩像素数据的文件
   原先会留下空白图片。现在先校验 JPEG 像素，失败则返回错误，不新增文档、不改变原图。
   回归用例从自行生成的 JPEG 截取到扫描头，不依赖外部文件。
3. **优化编码的低质量 RGB JPEG 显示绿色条纹。** 蓝色图形导出为质量 40、优化编码
   JPEG 后，Pillow 读取仍是蓝色，原项目读取变绿。主解码器对非交错且降采样的扫描
   没有返回错误，因此仅在解码失败时备用读取不能修复它。
   现在 JPEG 显示、缩略图、吸管、重新着色、描摹/马赛克、Trim Image、Unembed 转换
   和 Save for Web 预览共用正确的像素解码路径；CMYK 渲染仍保留工作配置下的墨量显示。
   新增三种 JPEG 编码方式的颜色回归，验证蓝色不会变成绿色。
   首页最近文件的 JPEG 预览也使用同一解码器，并保留原先的尺寸/内存限制和 EXIF 方向。
4. **优化编码的低质量 CMYK JPEG 触发解码器内部异常。** 实际桌面矩阵在质量 40、
   优化编码组合下发现越界；保护层捕获异常并保留文档，但渲染与导出失败。
   用 320×240 的原创蓝色图形复现，新增测试在修复前同样失败。
   CMYK 像素改为直接使用稳定解码器，避免调用会异常的路径；仍保留原始墨量、
   YCCK 转换、工作色彩配置及 64M 像素上限。

## 性能问题仍存在

执行 `vectorcraft-cli perf`，合成 50,000 路径。前两次使用修复前的优化 release；
关闭测试窗口后的复测负载均值为 0.2，程序可见 5 核，云环境 CPU 配额为 4 核。
最后使用修复后的发布版，待 CI、打包及窗口测试结束后运行；负载均值 0.1，程序可见
4 核。三次都未通过全部预算，没有调宽预算或跳过失败。

| 操作 | 修复前首次 / 关闭测试窗口后 | 最终发布版 | 预算 |
|---|---:|---:|---:|
| 整页渲染，2880×1800 | 182.63 / 197.38 ms | 418.25 ms | 100 ms |
| 平移后的后台重绘 | 183.18 / 230.49 ms | 454.73 ms | 100 ms |
| 400% 放大渲染 | 52.76 / 65.43 ms | 190.31 ms | 16 ms |
| 命中测试，每次点击 | 1.10 / 1.10 ms | 2.50 ms | 2 ms |
| 原生文件保存 | 103.24 / 146.34 ms | 196.71 ms | 300 ms |
| 原生文件打开 | 487.31 / 535.03 ms | 961.57 ms | 300 ms |
| SVG 导出 | 316.96 / 325.09 ms | 569.99 ms | 500 ms |
| Pathfinder Unite，1,000 路径 | 60.77 / 60.78 ms | 196.94 ms | 150 ms |
| 5,000 锚点手柄拖动，每次移动 | 7.76 / 7.89 ms | 10.86 ms | 8 ms |
| 5,000 锚点线段拖动，每次移动 | 7.29 / 9.61 ms | 7.97 ms | 8 ms |

整页、平移、放大渲染及原生打开在三次运行中都超预算；线段拖动在第二次超预算。
最终发布版 8 项超预算，仅保存和线段拖动通过，因此当前性能验收失败。
云机器测量有调度波动，程序可见核数也发生变化；目前没有足够证据把三次的速度差异
归因于 JPEG 修复，也不能宣称所有机器具有同样速度。结果说明本环境未达到既有
大文档预算，这些性能缺口保留为后续优化工作。

## 边界与复现

- Touch Type、3D/材质、Variables、SVG Interactivity、拼写检查及部分窗口排列仍属于
  [路线图](../ROADMAP.md) 已知未实现功能；部分偏好仍仅保存，未完整影响行为。
- 未在本轮验证真实显卡、手写板/压力、中文输入法候选窗口、系统文件选择器/portal、
  ARM64、物理打印机、色彩校准设备、
  Fedora/RPM 安装、Flatpak 安装或全部插件。WASM 编译门禁不等于浏览器运行验收。
- 没有外部复杂作品集或可选字体仓库时，相应条件测试不能算实际外部素材覆盖。
- 桌面流程使用临时原创作品，只有恢复测试使用独立的临时偏好目录，所有进程只停止自身
  启动的实例；截图和完整日志保存在本次工作区 `.kaleiform-env/full-qa/`，未提交为应用资产。
- 持久回归：`cargo test -p vectorcraft-doc progressive_cmyk`、
  `cargo test -p vectorcraft-engine progressive_cmyk`、
  `cargo test -p vectorcraft-engine a_jpeg_without_pixel_data`、
  `cargo test -p vectorcraft-engine optimized_rgb_jpeg`、
  `cargo test -p vectorcraft-engine optimized_cmyk_jpeg`、
  `cargo test -p vectorcraft-ui-egui jpeg_previews_keep_their_colours`。
- 性能复现：`cargo run --release -p vectorcraft-cli -- perf`；慢测试使用对应 effects、
  pathops、trace 包的 `cargo test --release -- --ignored --nocapture --test-threads=1`。

最终代码增加 6 项持久回归测试。桌面、描摹与修复后复查共 415 项检查通过；
接口、跨进程剪贴板、恢复和外部格式读取另行验证。
最终证据包括 `ci-cmyk-final.log`、`release-complete.log`、
`jpeg-fixed/results.json`、`jpeg-fixed/cmyk-progressive.png`、
`installed-x11.log`、`installed-wayland.log`、`portable-current.log` 和
`performance-final.log`。
更新的预览产物位于 `dist/release/`；本轮未发布到 GitHub Releases。
